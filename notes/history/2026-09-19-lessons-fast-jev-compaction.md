# 历史记录：从 fast-jev-compaction 学到什么（2026-09-19）

> 已采纳项并入：token 估算公式 → notes/jev-api.md；纯库 + 适配器、统计对象 → PLAN.md 架构节；阶梯降级、单来源失败处理、并发闸、配置校验 → notes/shadow-mode-logging.md；函数钩子路线 → PLAN.md 路线表。本文保留原始分析。文中"第 N 节"指 PLAN v2 节号。

对象：`~/Desktop/fast-jev-compaction`（tamaratran，MIT，v0.3.0，Devin 生成的 PR 为主，带 vitest 单测）。它用 Jev 替代 Claude Code 的压缩摘要：把整段对话当 state 发给 Jev，对每个工具调用问两道 noul（"调用本身还要不要留"、"结果原文还要不要留"），按阈值删或截断，留下的全部原样，不改写任何文字。同时是 npm 库和 Claude Code 函数钩子插件。

和我们的项目同构：都是"Jev 只做门槛裁决，幸存内容原样保留、不重排、不改写"。下面按"直接采纳 / 借结构 / 不采纳"分三档。

## 一、直接采纳

### 1. 不用分词器的 token 估算公式（已用我们的夹具验证）

规则：英文单词算 1 token，每多 6 个字母再加 1；数字每位算 0.5；其余任何符号（含每个 CJK 字符）算 0.9。

用 `fixtures/*.jev.json` 里 Jev 真实回报的 `usage.input_tokens` 对比（英文来源，每来源一次请求，含题库）：

| 夹具 | 实际合计 | 估算合计 | 估/实 | 单来源范围 |
|---|---|---|---|---|
| default 12 源 | 21475 | 22527 | 1.05 | 1.00–1.11 |
| strict 12 源 | 15659 | 15723 | 1.00 | 0.94–1.08 |

对比之下 "字符数 ÷ 4" 全部低估 10–20%，"÷ 3" 全部高估 20–30%。结论：这条公式在英文 JSON 请求体上准得多，**但不保证偏高**（strict 夹具里有 0.94），用作 32k 门槛保护时要再加 15% 余量。CJK 未验证（两份夹具 CJK 字符为 0），公式把每个汉字算 0.9，与我们"中文按 1 字符/token"的保守假设一致，影子期用中文样本再校。

用途：发送前的超限保护、日志里的 token 统计、状态行里的"过滤前后 token 对比"。脚本 `~/.zcode/tmp/260919-145125/est_check.py`。

### 2. 传输与逻辑分离，测试不碰网络

它把 Jev 客户端拆成三层：`buildJevRequest`（纯函数，产出 URL / 头 / body）、`parseJevResponse`（纯函数，校验形状）、`JevAsker` 接口（只有一个 `ask(state, questions)`）。单测里塞一个假的 asker，按题名返回固定概率；真实网络只在 demo 里走。

对我们的意义：三后端（直连 / OpenRouter / Vercel）差异全部收在 request 构造与 response 解析两个纯函数里，裁决层只认 `JevAsker`。我们已经有的 `fixtures/*.jev.json` 就是现成的"录像"：写一个回放 asker，按 source id 返回录好的答案，裁决层的测试可以离线跑完整 12 源流程。

### 3. 核心库与挂载点分离

仓库结构是 `src/`（与宿主无关的库，输入输出都是普通对象）+ `hooks/`（十几行的适配器，把宿主事件翻译成库调用）。库不知道自己跑在哪。

对我们的意义：过滤层新目录应当是**不含任何 MCP 类型**的纯库：输入 Brave 响应 JSON + 请求参数 + intent，输出过滤后的 JSON + 统计对象。上游 `execute()` 里只留一个几行的适配。这样：
- 单测和命令行对比工具直接调库，不起 MCP 服务器；
- 挂载点变化（见第三档的函数钩子）只换适配器，库不动；
- 上游合并冲突面最小。

这不改变 A2 决策，只是把"一个新目录"的边界画清楚。

### 4. 统计对象随结果一起返回

`compact()` 返回 `{messages, decisions, stats}`，stats 里有前后字符数、各原因计数、state 落在哪一档、请求数、耗时。状态行和日志都从同一个 stats 生成，不各算各的。我们的状态行（按原因计数）和 JSONL 日志应共用一个统计对象。

### 4b. 几条小而对的工程习惯（平行会话已提出，此处合并）

- **无候选就不调 Jev**：它在没有可裁的调用时直接返回、请求数记 0。我们本地规则层删光来源后同样跳过 Jev。
- **配置校验**：每个数值选项经 `finite()` 检查，NaN / 非数字回落默认值，负数截到 0。我们的环境变量阈值同样要校验，坏值不能让整层静默失效。
- **单来源请求失败只影响该来源**：我们是每来源一次请求，某一次超时或 429 时，只把那个来源按"留"处理（等价于对它只跑本地规则），其余来源照常裁决；熔断计数跨请求累计，连续 3 次失败才整体停 60 秒。这是对 PLAN 第 11 节第 5 条的细化。
- **进程级并发上限**：它把一次压缩的多批请求全部并发。我们一次搜索就是 12 个并发请求，模型再并行发几次搜索就翻倍；需要一个进程级的并发闸（初值 6，已实测 6 并发无限流），超出排队。

## 二、借结构，改内容

### 5. 超限时按阶梯降级，记录用到哪一级

它的 state 装不进 25k 时不是一刀切，而是一串越来越有损的变换，只在上一级不够时才用下一级，并把用到的级别名写进 stats：先截工具输入到 1000 → 200 → 60 字符，再把长文本缩成头尾，再把旧消息折成一行，再把旧调用压成一行，再丢掉无调用的旧消息，再合并连续调用；全部不够才抛错。

我们单来源请求通常 1–2k token，离 32k 很远，这套东西不急。但第 11 节第 6 条"超了就砍末尾片段"可以写成同样的阶梯，且每级都记名：
1. JSON-LD 元数据已删、导航片段已预筛（本来就做）；
2. 按 Brave 序砍尾部片段；
3. 去掉片段级 score 题，只留来源级 noul；
4. 仍超 → 该来源不问 Jev，走本地规则。

### 6. 两道正向"保留题"配三种结局

它对每个调用问"调用要留吗"、"结果原文要留吗"，都是正向措辞，然后代码分三档：结果留、只留调用加 300 字符开头、整个删。这从独立项目验证了我们 v2 的转向：**问正向的保留题，不达标才丢**，而不是问"这是不是垃圾"。我们的三档对应：来源留、来源留但片段只留高分句、来源丢。已经在方案里，不用改。

### 7. state 里带一句"情境说明"

它的 state 有个 `context` 字段，一句话告诉 Jev 这是在压缩对话、结果已被替换成摘要、删掉的东西模型可以重新执行。官方 cookbook 的 RAG 例子没有这种框架句。Jev 字面读题，这句可能帮它理解 `intent` 的用途，也可能是无关内容。放到影子期做一次对照，不默认加。

### 8. `goal` 取最近三条用户消息 ≈ 我们的 `intent`

它没法让模型显式给 goal，只能从最近的用户消息推。我们让调用模型必填一句英文 intent，判据更明确。维持。

## 三、不采纳，或它比我们弱的地方

- **默认 `jev-latest` 不钉版**：我们已定钉版 + 样本回归。
- **客户端没有超时、重试、熔断**：任何失败直接抛，由钩子兜底回内置摘要。我们照 mastra 模式做。
- **没有影子模式、没有逐请求日志**：只在 UI 打一行决策摘要。我们的影子期是定阈值的依据，必须有。
- **单一阈值 0.5 两题通用，无校准数据**：我们等影子期数据。
- **题干里嵌数字**（"结果 4213 字符"）：Jev 数值弱，这对它无用。我们题干不带数字。
- **每批都重发完整 state**：它的 state 是整段对话，被迫如此；我们单来源，无此问题。
- **`minReductionRatio` 门槛**（省不到 25% 就不替换）：它替换有代价（丢摘要），我们过滤零代价，丢一个来源也值得。不需要。
- 它自己标的"估算落在真实值上方 2–18%"，在我们夹具上不成立（有 0.94），见第 1 条。

## 四、挂载点：函数钩子是路线表里没有的第四条路

它用的是 Claude Code **函数钩子**（`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`，2.1.274 起的早期访问功能）：插件里一个 TS 模块，用 `on("session.compact", ($, e, next) => …)` 这种形式接管引擎事件。类型定义（`types/claude-code.d.ts`，11k 行）里同样有 `tool.call` 事件，可以按 `{ tool: "mcp__brave__brave_llm_context" }` 匹配，`await next(e)` 拿到真实结果后返回自己改写的 `{ result }`；还有 `tool.describe` 改工具描述、`$.http.fetch` 走宿主网络。

也就是说，过滤层理论上可以**不碰上游服务器**，作为一个 Claude Code 插件套在 brave 工具外面：

| | A2 源码嵌入（现方案） | 函数钩子插件 |
|---|---|---|
| 上游升级 | git 合并 | 零成本，继续用 npx 官方包 |
| 适用客户端 | 任何 MCP 客户端 | 只有 Claude Code |
| 版本要求 | 无 | CC ≥ 2.1.274 + 早期访问开关；类型每版重生成，README 自己写"可能随版本变化" |
| 本机可用 | 是 | **否**，本机 2.1.258（npm 最新 2.1.278） |
| 发布形态 | 独立 MCP 服务器仓库 | 插件市场 `claude plugin install` |
| 老大"不改 CC"原则 | 不碰 | 不改 CC 本体，但依赖其早期访问接口 |

结论：**维持 A2**。原因排序：本机版本跑不了；早期访问接口不稳；A2 产物对任何 MCP 客户端有效。但按第 3 条把核心做成纯库，将来本机 Claude Code 升到 2.1.274 后，写一个二十行的 `tool.call` 适配器就能把同一个库挂成插件，两条路不互斥。

顺带：Claude Code 插件也能打包 MCP 服务器（插件内 `.mcp.json`），发布阶段可以让安装变成一条 `claude plugin install`，不用手改 `~/.claude.json`。这是阶段二之后的事。

## 五、如果老大想直接用这个压缩插件

本机 2.1.258 跑不了，需要 2.1.274+ 并开早期访问开关，且它的 `types/claude-code.d.ts` 按 2.1.274 生成，升级后要重新生成核对。它没装依赖（无 node_modules），要 `npm install` 后才能 `npm test`。
