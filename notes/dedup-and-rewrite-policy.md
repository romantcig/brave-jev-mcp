# 重复与转述稿的处理原则（2026-09-19 定稿）

依据：老大 2026-09-19 的裁决。本文件是"改写稿 / 转述稿 / 重复内容"这一类的唯一权威说明，PLAN.md 只引用不复述。

## 原则

1. **按重复内容裁，不按来源身份裁。** 一篇转述稿（"彭博社据《金融时报》报道"）该不该留，只看它的内容有没有在前面幸存的来源里出现过。原文抓到了，转述没有新增就丢；原文没抓到，转述就是唯一可读版本，留。
2. **不是二极管。** 有一点重复不等于整页丢。重复的部分删，独有的部分留，整页只有在没有任何独有内容时才丢。
3. **粒度是片段。** 重复判断在片段级做，来源级的"丢"是片段全部被删之后的自然结果。
4. **Jev 不做跨来源比较。** "别处有没有说过"是代码的事。Jev 的 is_attributed_rewrite 只回答"这一页的事实是不是标注转引自别处"，它单独不能丢任何东西，只在代码判定重复时作确认信号，用来降低误删原创的风险。

## 算法：事实指纹增量新颖度（片段级）

按 Brave 原序遍历来源，来源内按原序遍历片段：

- 指纹元素：数字（含单位、货币前后缀）、日期串、专有名词（连续大写词组、书名号 / 引号内容）、≥ 6 词的引号原文、代码标识符（反引号内容、`foo.bar()` 形态）。
- 维护"已幸存指纹并集"。每个片段算 `novel = fp(片段) − 并集`。
- 片段判为重复并删除：`|fp(片段)| ≥ MIN_FACTS`（有足够事实可比）且 `|novel| < NOVELTY_MIN`。事实太少的片段不在此删，交给片段级评分。
- 片段幸存则把它的指纹并入并集。
- 来源的片段全部被删 → 来源丢，原因记 `rewrite`。部分被删 → 来源留，状态行计入"n 片段重复"。
- 5-gram shingle 逐字重复（通稿转载、页内标题导语重抽）在指纹之前先做一遍，两者互补：shingle 抓逐字，指纹抓改写。

## 例子

| 场景 | 结果 |
|---|---|
| 彭博原文在前，五篇"据彭博报道"在后 | 五篇里逐句转述的片段删；某篇加了自己的行业数据，那一段留，来源留 |
| FT 原文付费墙抓不到，彭博转述 FT | 彭博片段指纹全新，全留 |
| 官方公告 + 十篇改写 + mezha 独有引语 | 十篇改写大部分片段删，mezha 独有引语那段留 |
| 两篇原创评论，事实相同、论证不同 | 论证段没有数字 / 专名指纹，不进重复判定，交给 Jev 的 has_original_reasoning，都留 |

## 已知边界

- 措辞完全不同但事实完全相同的第二篇会被删，这是期望行为。
- 指纹抽不到的纯观点段落不受此规则影响，靠 Jev 的原创论证题保护。
- 阈值 `MIN_FACTS`、`NOVELTY_MIN` 初值见 shadow-mode-logging.md，影子期修订。
