# Brave Jev MCP

[English](https://github.com/romantcig/brave-jev-mcp/blob/release/README.md) | 简体中文

AI 联网搜索时，拿到的内容经常混着空泛文章、网站导航，以及提到了关键词却回答不了问题的段落。这些内容会占用上下文，也让 AI 需要从更多无关信息中寻找答案。

**这个项目在 `brave_llm_context` 的搜索结果交给 AI 之前，先筛掉其中无用的页面和片段，让 AI 把更多上下文留给真正能帮助回答问题的内容。**

项目基于 [Brave Search MCP Server](https://github.com/brave/brave-search-mcp-server)：Brave 负责搜索网页、提取内容，[Jev](https://typesafe.ai/) 负责结合搜索目的进行筛选。留下的内容仍然带有来源链接，并保持 Brave 的原始顺序，方便 AI 阅读、回答和引用。

**过滤范围：目前只有 `brave_llm_context` 接入了本项目的过滤层。其他搜索工具仍可使用，但不支持这套过滤，也不会调用 Jev 进行筛选。下文的过滤配置、状态和调试样本均仅适用于 `brave_llm_context`。**

## 安装接入

先准备好：

- [Node.js](https://nodejs.org/)，推荐使用 24 LTS。
- [Brave Search API 密钥](https://brave.com/search/api/)，用于搜索。
- [Jev API 密钥](https://typesafe.ai/)，用于过滤。

在 AI 客户端中添加下面的配置，`npx` 会自动下载并启动，无需下载源码或手动构建。以下示例适用于使用 `mcpServers` JSON 配置的客户端：

```json
{
  "mcpServers": {
    "brave-jev": {
      "command": "npx",
      "args": ["-y", "@romantcig/brave-jev-mcp@0.1.1", "--transport", "stdio"],
      "env": {
        "BRAVE_API_KEY": "你的 Brave Search API 密钥",
        "TYPESAFE_API_KEY": "你的 Jev API 密钥"
      }
    }
  }
}
```

把两项密钥占位符换成自己的密钥。示例固定使用 `0.1.1`，便于保持版本稳定；希望跟随最新版时，将 `@0.1.1` 改为 `@latest`，更新时重启 MCP。其他格式的客户端配置，也填写相同的启动命令、参数和环境变量。

首次启动时，程序会自动创建 `~/.brave-jev/config.json`，默认开启过滤；已有配置会继续使用。Brave 密钥是搜索所必需的。暂未配置 Jev 密钥时，搜索仍然可用，会跳过 Jev 过滤，并在需要过滤的结果中提示如何配置。修改密钥或配置后，重启 MCP 即可生效。

## 接入后怎么用

直接向 AI 描述需要查找的内容。例如：

> 使用 Brave Jev MCP 的 `brave_llm_context` 比较 SQLite 和 PostgreSQL。我想为一个单机应用选择数据库，重点了解部署复杂度、并发写入限制和适用场景，请附上来源。

AI 调用本项目的 `brave_llm_context` 后，搜索、内容提取和过滤会在这次调用中完成。AI 收到筛选后的网页片段及来源链接，再据此组织回答；需要进一步核实时，可以继续访问原页面。如果客户端同时接入了多个搜索工具，可以明确要求 AI 使用本项目的 `brave_llm_context`。

**把“为什么要搜”一起说清楚，能让筛选更贴近实际需求。** 比如，为单机应用选择数据库时，并发限制和部署方式有用，泛泛介绍“数据库很重要”的段落则帮助不大。AI 会把关键词和搜索目的分别传给工具，你只需把自己的需求说清楚。

日常使用已有默认的搜索数量和内容预算，需要更多来源或细节时再调整。Jev 暂时不可用时，程序会返回经过本地清理的搜索内容。

### 核对过滤结果

如果想知道某次搜索删了什么，可以将 `~/.brave-jev/config.json` 中的 `mode` 改为 `test`，然后重启 MCP：

```json
{ "mode": "test" }
```

这时每次调用 `brave_llm_context` 都会保存一份本地样本，并在返回结果中附上文件路径。下面是一条实际返回的过滤状态，本机路径已替换为占位符：

```text
[filter] 4 snippets removed sample for filter debugging - original results, filtered results, Jev decisions: <本地样本路径>
```

这条状态表示移除了四个片段，后面的路径指向本次搜索的完整样本。如果觉得某次搜索删掉了有用内容，或留下了明显无用的内容，可以让能读取本地文件的 AI 检查这份样本：

> 请读取这次搜索返回的样本文件，对照过滤前后的内容，检查有没有误删或漏删，并结合 Jev 的判断说明原因。

样本里保存了原始搜索结果、最后留下的内容、发给 Jev 的题目和它的回答，可以对照具体内容看每一步发生了什么。核对完成后，将 `mode` 改回 `on` 并重启，就会恢复日常模式，不再额外保存完整样本。

## 三片组合过滤

Brave 返回的网页内容已经拆成多个片段，有些片段甚至只有一句话。为了保留一篇文章中的有用信息、删掉其中无用的部分，我们需要逐片判断；如果只判断整页，就只能整页保留或整页删除。

如果对每个片段分别提问、打分，再按门槛决定删留，那么 Brave 返回 **800 个片段，就需要准备 800 道判断题**。同一套筛选要求，也要随这些题目重复发送。

问题在于：**一个片段可能只有一句话，描述判断标准的题目却有上百 Tokens。** 大量 Tokens 花在反复说明“应该怎样判断”，实际需要判断的内容反而很少。

把多个片段合在一起，只给整组内容打一个分，可以减少重复提问，但这个分数无法告诉我们哪些片段该留、哪些该删。

比如，A 是数据库的并发写入限制，B 是网站导航，C 是部署步骤。整组保留，导航也会跟着留下；整组删除，并发限制和部署步骤也会一起丢掉。我们需要表达的是“留下 A、C，删除 B”，而整组的一个分数无法直接表达这三项决定。

于是，我们将**同一来源的连续三个片段**放进同一道 Choice 单选题，**让题目可以共用，删留仍然分别判断。**

A、B、C 分别代表三个片段，选项中的字母表示要保留的片段。例如，`A` 表示只留 A，`AB` 表示留下 A 和 B，其余删除。三个片段可以组成以下八种选择：

> A、B、C、AB、AC、BC、ABC（全留）、none（全删）

在刚才的例子里，`AC` 就表达“保留并发限制和部署步骤，删除网站导航”。**一套筛选要求只需写进一道题，就能表达三个片段分别保留还是删除。** 来源末尾只剩两个或一个片段时，也会按剩余数量组成题目。

实际处理答案时，还会考虑每个选项的概率。比如，`A`、`AB`、`AC`、`ABC` 都包含“留下 A”这个意思，我们把这四个选项的概率加起来，再判断 A 是否值得保留。这样，对同一片段的判断就能综合多个选项的结果，最后仍然逐片决定删留。

一次搜索的内容和题目放在同一个请求里发送，正文只放一份；三个片段共用一道题，又减少了筛选要求的重复。省下题目开销的同时，我们仍然能分别处理每个片段。

一组放入更多片段，也会带来新的开销。三个片段需要八种组合，四个就需要十六种，每增加一个片段，选项数量都会翻倍。Jev 的单选题最多支持 255 个选项，而八个片段的完整组合已经需要 256 个。我们将每组固定在三个片段，既减少重复题目，也让每道题的选项数量保持可控。

## 临界阈值补偿

按分数决定删留，还会遇到另一个问题：有些内容明明已经倾向于删除，却因为离门槛差一点而被留下。

例如，我们规定垃圾概率达到 `0.80` 才删除页面，那么得到 `0.78` 的页面就会保留。检查样本时，我们发现一些缺少实质帮助的内容正好落在门槛附近，单靠这条分界线会把它们留下。

为此，项目加入了一个小范围的补偿：**在删除门槛附近，再考虑相差不超过 `0.02` 的判断。** 对上面的页面来说，`0.78` 也会触发删除。这是我们根据边缘样本的情况采用的范围，用来处理那些只差一点就达到删除条件的内容。

片段也采用同样的思路：保留概率偏低时删除；即使刚达到保留门槛，但高出不超过 `0.02`，也会删除。模型给出的原始概率保持不变，补偿只影响最后是否删除。某项门槛设为 `0` 或 `1` 时，该项不使用补偿。

## 其他配置

日常使用保持 `mode: "on"` 即可。想检查完整样本时用 `test`；想关闭 Jev、只保留本地基础清理时用 `off`。修改后都需要重启 MCP。

如果需要把配置放在其他位置，可以通过 `JEV_FILTER_CONFIG_FILE` 指定文件路径，并自行创建该文件。完整配置、阈值和日志说明见 [过滤层配置指南](https://github.com/romantcig/brave-jev-mcp/blob/release/FILTERING.md)。
